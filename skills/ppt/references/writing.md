# PPT 内容与叙事

先服务观众任务，再追求句子漂亮。事实、观点、建议、假设、示例和隐喻可以同时存在，但必须让它们保持正确身份。

## 叙事

- 使用 [archetypes.md](archetypes.md) 的任务模式帮助思考，不照抄固定页序
- 一页通常完成一个认知动作：建立问题、解释关系、展示变化、提供证明、制造停顿或推动决定
- 重要内容可以连续讲多页；过渡和留白页也可以成立，不需要每页都塞满信息
- 页间建立因果、对照、空间或情绪联系；没有联系时直接切换，不强造金句桥梁
- 同一对象跨页继续存在且运动能帮助理解时，列为共享元素候选；只是外观相似时不要绑定
- 开场与收尾服从任务：决策稿可以直接给请求，主题演讲可以先建立张力，培训可以先给学习目标；不强制议程、CTA 或“谢谢”

## 主张的身份

| 内容性质 | 如何使用 |
| --- | --- |
| 用户提供事实 | 可直接使用，notes 写明材料来源或“用户提供” |
| 外部事实或量化主张 | 引用可信来源、完成研究、让用户确认，或使用 Todo |
| 可复算推导 | 写清输入与公式，避免把推导当实测 |
| 建议、目标与方案 | 明确其建议或目标身份，不需要伪造外部权威 |
| 教学示例与虚构场景 | 可以创作，但必须让观众知道它是示例 |
| 观点、故事与隐喻 | 可以作为表达主角；不要伪装成行业共识或真实引语 |

缺失的关键事实使用 `<Todo owner="确认人或来源">`。草稿交接时逐页解释；正式导出前补齐、删除主张，或改成用户确认的可见假设。

## 文案

- 标题承担导航或判断功能：可以是对象、问题、动作、结论、引语或刻意留白的短句
- 结论式标题需要被同页内容或演讲上下文支撑；准确点题不等于所有标题必须是名词短语
- 页面文案以现场可读为准，长推导、详细来源和讲法进入 notes；代码、表格和引用页可以合理更密
- 不为气势自动生成全大写英文眉题、英文翻译、三段式价值观或“不是 A 而是 B”式口号
- 用户、品牌或场合真实提供的会议名、系列名、英文专名和双语要求可以使用
- 来源默认放 notes；学术、合规、外部销售或用户要求时，允许在页面贴近对应主张显示引用
- 完成首稿后按需阅读 [voice.md](voice.md)，只改有 AI 痕迹的片段，不统一改成另一种模板口吻

## 数字与数据

- 先确认口径、单位、范围、时间和比较对象，再决定图表形式
- 中位数、均值、累计值、百分比和预测值遵循各自统计含义，不做无法成立的运算或因果推断
- 趋势、对比和结构使用合适图表；一个数字本身有意义时可以只展示数字，不为“可视化”制造伪图
- NumberFlow 用于被揭示、比较、变化或强调的量化结论；表格、坐标轴、密集辅助值、日期、版本和 ID 保持静态 tabular numerals
- 同页多维数字应来自兼容口径，notes 记录必要限定

## 视觉与内容关系

- 真实产品、地点、人物或物件是主题时，优先展示可辨认的真实素材
- 数据、机制和流程优先用图表、架构、时间线或题目专属图解
- 人物关系可以用照片、手绘演员、服务蓝图、流程节点或真实界面，按设计方向选择
- 视觉隐喻可以承担观点和情绪，不要求每个画面都是证据；但装饰不能妨碍阅读或伪装成信息
- 封面可以留白、full-bleed、split、产品实物或主题场景，选择取决于第一眼应该建立什么
- 不把某个演讲的墨梅、签名、纸纹、衬线和手绘小人泛化成通用风格；匹配时读取 [recipes-personal.md](recipes-personal.md)
