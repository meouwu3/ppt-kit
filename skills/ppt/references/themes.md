# 视觉系统与 Token

`src/styles/tokens.css` 是视觉事实源。现有 `paper`、`studio`、`night` 只是可运行预设，不是所有演示的推荐风格；新 deck 可以覆盖或增加主题。

历史 token 名 `--paper` 和 `--ink` 分别表示背景与前景角色，不要求画面真的像纸和墨。

## 从意图到值

先在本次设计声明中定义：

1. **视觉意图**：品牌气质、信息密度、中性色温、语言与媒介
2. **视觉角色**：背景、前景、弱文字、边框、主强调、状态、图表和媒体表面各自承担什么
3. **视觉值**：颜色、字体、版式、间距、形状、阴影、动效与层级
4. **派生关系**：强调色如何生成 soft/strong，密度如何联动间距与圆角，状态如何从基础角色派生
5. **缺口处理**：缺少 token 时先复用最接近的语义角色；确实需要新角色时记录原因并在主题层增加，不在页面散落字面量

只给颜色值会让 Agent 不知道怎么用，只给抽象气质会让它自由补成常见 AI 模板。意图、角色和值要同时成立。

## 核心角色

- `--paper`、`--paper-raised`：背景与抬升表面
- `--ink`、`--ink-muted`、`--ink-faint`：主要、辅助与弱前景
- `--line`、`--line-strong`：结构分隔与坐标
- `--accent`、`--accent-strong`、`--accent-soft`：主强调及派生表面
- `--good`、`--warning`、`--danger`：可用状态角色；业务含义由当前 deck 定义
- `--font-display`、`--font-sans`、`--font-serif`、`--font-mono`：展示、正文、备选衬线与代码/数字字体
- `--radius-*`、`--shadow-*`、`--space-*`、`--ease-out`：形状、深度、间距与运动
- `--paper-texture-opacity`：可选纹理；设为 0 即关闭
- `--plum-*`：仅供 `InkPlum` 可选配方使用，不属于通用品牌主题必填项

组件使用语义 token，不写散落的品牌 hex。题目专属 SVG、Canvas 或图表也应从 token 读取颜色。

## 品牌输入

用户提供品牌规范、网页或旧 PPT 时：

- 提取真实颜色、字体、Logo、图像风格、圆角/线条、密度和动效线索
- 记录来源 URL 或文件，不凭印象声称“这是品牌色”
- 把品牌值映射到语义角色，而不是把 Logo 色铺满所有元素
- 在交付说明中报告使用了哪些品牌来源和哪些自主设计判断

没有品牌输入时，根据任务与设计方向主动选择视觉系统。可以大胆，但要在设计声明中解释意图，不默认紫蓝渐变、玻璃卡、纸张衬线或任何固定“高级感”。

## 字体与交付

导出是整图，因此交付端不需要字体兼容；本机预览仍要使用明确字体栈。中文、西文、代码和数字的角色按主题配置。联网字体会降低离线稳定性，只有授权、网络与导出环境明确时才使用。

替换主题后检查文字对比、图表语义、媒体可辨认性、纹理/阴影强度、最长文案和 print 终态。
