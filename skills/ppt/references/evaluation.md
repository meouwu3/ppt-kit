# 评估、证据链与交付闸门

评估的目标不是给审美一个虚假的精确总分，而是判断当前阶段能否放行、问题来自哪里、下一轮只改什么。

## 三种评审模式

| 模式 | 关注点 | 允许 | 放行条件 |
| --- | --- | --- | --- |
| 方向稿 | 叙事主线、视觉概念、注意力顺序 | Todo、局部占位、代表页 | 方向能解释且适合听众 |
| 可评审稿 | 完整页序、关键内容、代表性动画 | 少量已说明 Todo | 主线可讲、关键页面成立、运行无错误 |
| 最终稿 | 内容、视觉、notes、导出产物 | 不允许 Todo 或模板页 | 所有阻断清零，构建和正式导出通过 |

评审模式只改变放行条件，不把方向稿的视觉问题伪装成“以后再说”，也不拿最终集成标准阻止早期探索。

## 六个维度

所有类型使用同一组维度，但重要性不同：

1. **听众意图**：观众是谁，应该注意什么，结束后理解、决定或行动什么
2. **内容可信**：事实、领域语义、数字、引语、不确定性和建议的身份是否准确
3. **叙事架构**：顺序、层级、节奏和信息密度是否服务理解与决策
4. **现场就绪**：讲述路径、步进、状态变化、共享元素、控制和静态终态是否成立
5. **系统工艺**：字体、间距、组件、图表、资源、可读性和导出是否像一套系统
6. **视觉表达**：视觉概念、品牌/品类匹配、图像、构图、动效和记忆点是否独特而有用

不同任务调整主次，不复制固定权重：

- 决策与经营汇报：听众意图、内容可信、叙事架构优先
- 晋升与技术复盘：内容可信、叙事架构、现场就绪优先
- 产品路演与主题演讲：听众意图、视觉表达、现场就绪优先
- 培训与教学：叙事架构、现场就绪、内容可信优先

每个维度记录 `pass / partial / fail`，并附具体页码和证据。不要先写结论再补理由。

## 证据链

1. **Browser QA**：控制台、页面错误、资源失败、文字越界、图片 alt、字体与导出就绪
2. **Click smoke**：逐步前进和回退，确认点击顺序、旧元素重排、共享元素和最终状态
3. **Slide screenshots**：检查文字真实可读、视觉层级、构图风险、品牌语气和动效目的
4. **Contact sheet**：检查整套节奏、重复模板、密度突变、视觉主角缺失和不一致素材
5. **Build/export**：验证 PNG、PDF、PPTX、HTML、notes、页数和 manifest

DOM 说没有 overflow，不代表画面成立；当 DOM 与视觉判断冲突时，以观众实际看到的截图为准。截图判断也不能掩盖可确定的运行错误。

## 阻断问题

以下问题不能被“整体不错”平均掉：

- `unclear_primary_intent`：观众看不出本页或整套演示要表达什么
- `fabricated_or_misleading_claim`：事实、数字、引语或建议身份具有误导性
- `critical_rendering_failure`：遮挡、裁切、不可读、资源失败或空白画布
- `broken_presentation_path`：步进、前后翻页、演讲者模式、共享元素或关键状态无法完成
- `template_residue`：保留 starter 页、示例数据、默认标题或个人签名
- `generic_template_output`：整套演示换一个主题也成立，没有题目专属视觉和叙事判断
- `inconsistent_design_system`：字体、间距、色彩、圆角、图表或素材家族明显失控
- `visual_review_missing`：只跑构建，没有逐页截图与 contact sheet 判断
- `unresolved_final_content`：最终稿仍有 Todo、未说明假设或缺失 notes

## 评审输出

```text
模式：方向稿 / 可评审稿 / 最终稿
最强的 2 点：
六维度：每项 pass / partial / fail + 页码证据
阻断项：
下一轮只改的 1–3 件事：
回流目标：brief / 结构 / 内容组件 / 视觉系统 / 动效工艺 / 运行时
决定：通过 / 迭代 / 保留最佳版并请用户选择
```

优化指令只保留最影响放行的 1–3 项。无阻断且当前模式达标时停止；到达两轮自主修订、改善平台期或新版退步时，不继续无限微调。
